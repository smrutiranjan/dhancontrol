# Trade Count Kill Switch

[trade_count_killswitch.py](./trade_count_killswitch.py) polls Dhan's order list every 5 seconds. When the number of `TRADED` orders reaches `max_trades`, it activates Dhan's broker kill switch. It can also configure Dhan's automatic P&L exit. The process exits at **15:10 IST** daily.

## Files

| File | Purpose |
|------|---------|
| `trade_count_killswitch.py` | The monitor |
| `holiday_stop_trade_killswitch.py` | Weekend/NSE-BSE holiday check |
| `start_trade_count_killswitch.sh` | Starts the monitor in the background (cron-safe, pidfile-based) |
| `stop_trade_count_killswitch.sh` | Stops the monitor (pidfile plus process sweep) |
| `cred.yml` | Credentials and settings |
| `log/` | Daily logs (`trade_count_killswitch_YYYYMMDD.log`, `cron_stdout.log`) |

## Configuration (`cred.yml`)

```yaml
clientid: <your client id>
pin: <your pin>
totp_secret: <your totp secret>
token: <auto-generated and saved by the script>

max_trades: 20            # kill switch fires at this many TRADED orders (default 16)
max_daily_profit: 1000000 # required when pnl_exit.enabled is true
max_daily_loss: 10000     # positive number; required when pnl_exit.enabled is true
pnl_exit:
  enabled: true
  product_type: [INTRADAY, DELIVERY]
  enable_kill_switch: true
holiday_check_enabled: false
test_mode: false          # see "Test mode" below
```

Never commit or share `cred.yml`; it contains secrets.

## Startup checks

On normal startup the script exits before touching credentials or the API if:

1. It is a weekend, or outside **09:15–15:10 IST**.
2. The exchange calendar (XBOM) says it is a market holiday.

## Test mode (run outside market days/hours)

Set `test_mode: true` in `cred.yml` (or the environment variable `DHAN_TEST_MODE=1`) to bypass the startup weekday, market-hours, and holiday checks.

- It is **not** a dry run: the script still logs in and can activate the real broker kill switch.
- The 15:10 IST daily cutoff still applies. After 15:10 IST the monitor stops immediately.
- Set it back to `false` (or remove the key) for normal operation.

## Server deployment (Linux)

The default install directory is `/var/www/algo`. Override it with the `DHANALGO_DIR` environment variable.

### 1. Set the timezone to IST

```bash
sudo timedatectl set-timezone Asia/Kolkata
timedatectl                    # expect: Time zone: Asia/Kolkata (IST, +0530)
sudo systemctl restart cron    # RHEL/CentOS: crond
```

### 2. Schedule with cron (`crontab -e`)

```cron
CRON_TZ=Asia/Kolkata
15 9 * * 1-5 /bin/bash /var/www/algo/start_trade_count_killswitch.sh
10 15 * * 1-5 /bin/bash /var/www/algo/stop_trade_count_killswitch.sh
```

- Start: 09:15 IST, Monday to Friday.
- Stop: 15:10 IST, Monday to Friday. This matches the script's own cutoff.
- `CRON_TZ` is optional once the server timezone is IST.

### 3. Manual control

```bash
/bin/bash /var/www/algo/start_trade_count_killswitch.sh
/bin/bash /var/www/algo/stop_trade_count_killswitch.sh
```

The start script is a no-op if the monitor is already running. It looks for a Python interpreter at `venv/bin/python3`, then `.venv/bin/python3`, then system `python3`.

## Windows (development)

```powershell
cd D:\DhanAlgo
.\.venv\Scripts\python.exe trade_count_killswitch.py
```

To set the Windows timezone, run in an admin PowerShell: `Set-TimeZone -Id "India Standard Time"`.

## Logs and troubleshooting

- Daily log: `log/trade_count_killswitch_YYYYMMDD.log`; cron output: `log/cron_stdout.log`.
- "Outside the Monday-Friday, 09:15-15:10 IST run window": the server clock/timezone is wrong, or you started outside market hours. Check `timedatectl`, or use test mode.
- "holiday_stop: ... exiting": today is a weekend or market holiday.
- "Already running (pid N)": a monitor is active. Stop it first with the stop script.
- `get_order_list` failures: the script retries once after reloading the token from `cred.yml`. If failures persist, trade counting cannot trigger the kill switch; check the token and API access.
